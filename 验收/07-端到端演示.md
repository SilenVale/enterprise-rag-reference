# 端到端演示

状态：通过

## PDF 里要证明的规则

规则按提示词里「端到端」和「完成到什么地步」第 2 条来写。作品集的九段 README 不在这一层。

端到端把前面各层的演示收成一条命令。命令的输出要能看出每一层走了哪一格。这条命令要跑起这些演示：解析失败进入人工队列；子块命中后取回父块；同一内容哈希不重复入库；修订后查询在切换前仍读旧版；废止版本默认检索不到；无权限的角色检索不到受限制度；原问题和改写都参与召回；RRF 之后精排分成高、中、低三档；答案带编号；错误数字被拦住；废止引用被拦住；蕴含不支持的句子被删掉或整条降级；评测回退会阻断。

验收连的是本机 Milvus、Elasticsearch、对象存储和元数据库。内存替身不作为通过依据。BGE-M3 和 bge-reranker-v2-m3 用已经通过的加载方式。这一层不加载 Qwen2.5-72B。

## 测试命令

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
bash deploy/start-storage.sh
.venv/bin/python -m rag.demo
.venv/bin/pytest tests/demo -q
```

`python -m rag.demo` 是那条把各层演示收起来的命令。它打印每一格的名字和这一格走到了哪里。`pytest tests/demo` 对同一次行走再核对这些格子，并且同样连着四个服务。

## 最近一次结果：通过

`python -m rag.demo` 退出码 0。终端记录在 `docs/demo/e2e-terminal.txt`。当前证据是这份终端记录。这一层没有做屏幕录制。

`pytest tests/demo tests/evaluate -q`：55 passed in 15.05s。其中 `tests/demo` 15 条，`tests/evaluate` 40 条。评测门禁原来的 40 条仍在，没有改坏。

输出里能对上的格子：

- 存储：Milvus、Elasticsearch、对象存储、元数据库都已接通。实现分别是 `MilvusChildVectorStore`、`ElasticsearchChildTextStore`、`MinioBlobStore`、`PostgresMetadataStore`，地址是 `127.0.0.1` 上的 19530、9200、9000、5432。
- 数据接入，失败处置：双栏吞掉半栏的文件三次尝试后进入元数据库人工队列，状态 `queued`，没有进入索引。
- 索引工程，父子分块：子块从 Milvus 命中，父块从对象存储按编号取回。向量命中里没有父块正文。
- 索引工程，内容寻址：同一份规范化文本再从另一个来源进来，复用已有索引，没有再次嵌入。两个来源都留着。
- 索引工程，废止打标：新版本还停在 `pending` 时，查询指针和检索都还在 v1。切换之后，默认检索只看到 v2，废止的 v1 不出现；审计查询可以再把它带出来。
- 检索链路，三路召回：实习生的过滤条件是 `public`，在进引擎之前就写上。受限子块没有出现在候选里。未加权限时公开块挤不进前 50，所以这不是事后从结果里挑掉的。
- 检索链路，查询改写：原问题「那一条的上限是多少」和改写「差旅住宿标准第三条的上限是多少」都进了向量召回。改写模型是 `rule-rewrite`，不是 Qwen2.5-72B。
- 检索链路，RRF 和精排：融合分是各路 `1/(60+rank)` 之和。精排用已加载的 bge-reranker-v2-m3，三档分数是高 0.9977、中 0.5401、低 0.0000，去向分别是生成并引用、附上可能不完整、拒答并转人工。
- 生成防御，编号：本机档 `local-extractive` 写出的答案带 `[1]` `[2]`。权重没有加载。引用日志写在元数据库。
- 生成防御，数字：草稿里的 1750 对不上引用原文，整条被拦住，交卷里没有这个数字。
- 生成防御，版本：废止块上的句子被拦住，仍生效的那一句留下。
- 生成防御，蕴含：真实蕴含模型把「已经停发」判成不支持。这句话被删掉，得到支持的句子还在，删完仍然可读，所以没有整条降级。
- 评测门禁，回归：评测集写入元数据库再读回。把 topK 收到 1 之后，相对元数据库里的基线，Recall@5 回退超过阈值，门禁阻断。

BGE-M3 的名称是 `BAAI/bge-m3`，维度 1024。精排的名称是 `BAAI/bge-reranker-v2-m3`。Qwen2.5-72B 这一格标的是未加载。
