# 检索链路

状态：通过

## PDF 里要证明的规则

规则按架构里检索链路五格来写，用自己的话。答案正文、出口三道校验和评测门禁不在这一层。

- 多轮里的指代要带上对话历史，改写成可以单独拿去检索的问题。复合问题拆成 2 到 3 个子查询，各自检索后再合并。原查询一直参加召回。改写抛错时只留下原查询，原来能召回的子块还在。改写不调用生成主模型。材料没有写死改写模型的规格，选型标注「文档未写死」。
- 三路同时发出。向量一路是 Milvus 的 HNSW，查询向量用 BGE-M3。BM25 一路是 Elasticsearch，条款编号按完整 token 精确匹配，截断的编号对不上。元数据一路只按权限、生效状态、文档类型在引擎里圈定子集，不按词面打分，也不按向量打分。三路都把这些标量条件下推进引擎，各取最多 50 条。一次检索的延迟按最慢的那一路算。某一路引擎不可用，整次记为检索失败，不用另外两路的结果充数。
- 无权限的角色看不到受限制度。实习生夹具里，55 条更贴近问题的受限子块会占满不加权限条件的 top 50，那条公开子块进不了这 50 条。检索仍然能返回公开子块，受限子块不出现在任何一路、融合结果和精排结果里。通过依据不是先取出来再丢掉。
- 废止和未生效默认不出现。审计查询显式打开之后，废止版本可以出现，未生效的仍然不出现。
- RRF 的融合分是各路 `1/(60+名次)` 相加，名次从 1 开始。不把余弦相似度和 BM25 分数加权求和。某一路没有这个候选，这一路就不加分。
- 精排用材料点名的 bge-reranker-v2-m3。融合结果里取一段候选，排出前 5。这段候选的条数若落在 50 到 100，具体取值标注「文档未写死」。模型加载失败就停在这一层，验收不能改成通过，也不换别的模型。
- 按精排最高分分流，这一层不写答案正文。高分：生成答案并引用。中分：生成答案，并附上可能不完整、建议人工核实。低分：拒答并转人工，写入拒答日志。检索失败另记一条。高、中、低的分数线标注「文档未写死」。

## 测试命令

```bash
python3 -m venv .venv
.venv/bin/pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install -e ".[dev]"
bash deploy/start-storage.sh
.venv/bin/pytest tests/retrieve -q
```

第一次运行会下载 `BAAI/bge-m3` 和 `BAAI/bge-reranker-v2-m3`。权重缓存在仓库的 `.hf_cache/`，不进 git。

验收连的是已经通过的 Milvus `127.0.0.1:19530` 和 Elasticsearch `127.0.0.1:9200`。拒答日志写在 PostgreSQL `127.0.0.1:5432` 的库 `rag`。没有用内存字典或先取后滤当作这一层通过的依据。

向量集合用 `rag_retrieve_vectors`，维度 1024。倒排索引用 `rag_retrieve_text`。两者和存储层的 `rag_child_vectors`、`rag_child_text`，以及索引层的 `rag_index_children` 分开，避免把前面两层的演示数据撑坏。夹具写在 `tests/retrieve/`，不依赖 `corpus/`。

## 自己选定的参数

材料写了三路、top 50、RRF 的 k=60、BGE-M3、bge-reranker-v2-m3、先过滤和三档分流，没有写死下面这些实现细节。文档未写死。

- 改写器用仓库里的 `rule-rewrite`。它根据对话历史消解「那一条」「它的」这类指代，并在出现「分别」或「以及」时把复合问题拆开。它不加载 Qwen2.5-72B，也不和嵌入、精排共用同一个模型。文档未写死。
- 复合问题超过三段时只保留前三段。文档未写死。
- 精排候选数取融合结果的前 80 条，落在 50 到 100 之间。文档未写死。
- 三档看精排最高分的 sigmoid 值。大于等于 0.72 为高分，大于等于 0.30 且低于 0.72 为中分，低于 0.30 为低分。评测集还没建，这两条线只为这一层把三档跑通。文档未写死。
- 实习生只检索 `permission=public`。员工和审计员不再按这个标签收窄。认不出的角色按实习生处理。文档未写死。
- 元数据一路在引擎过滤后的子集上按 `child_id` 取前 50，名次只交给 RRF，不表示语义相关。文档未写死。
- 条款编号精确匹配走 Elasticsearch 的 keyword 字段。正文倒排沿用存储层已经建好的分析器。阅读笔记里的 IK 没有装进这台已经通过验收的 Elasticsearch，避免为了分词插件重启存储层。文档未写死。
- 向量集合名是 `rag_retrieve_vectors`，倒排索引名是 `rag_retrieve_text`。文档未写死。
- 拒答记在元数据库的新表 `retrieve_refusal`。这一层只记「检索失败」和「低分拒答」。知识补录队列不在这里。文档未写死。
