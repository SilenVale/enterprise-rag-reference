# 索引工程

状态：通过

## PDF 里要证明的规则

规则按架构里索引工程五格来写，用自己的话。查询改写、三路召回、RRF、精排、生成和评测不在这一层。

- 父块按条款切，长度落在 512 到 1024 token。同一章里偏短的相邻条款会并成一块，直到进入这个区间。子块再切到 128 到 256 token。
- 只有子块做嵌入，也只有子块写入向量库。父块全文不嵌入，向量集合里没有正文字段。
- 子块 metadata 带 `parent_id`、文档编号、版本号、内容哈希。父块原文写在对象存储。子块命中之后按 `parent_id` 把父块原文取回来。
- 送去嵌入的文本先拼上标题路径。表格按行切，每一行都带着表头，单独看一行也知道字段是什么。
- 表头补不回去时，整份表退回数据接入的表格闸门。不会把缺表头的格子当成普通段落切进索引。
- 父块超过 1024 token 时，先收成条款正文加条项说明，附加的长段不留在父块里。收完仍然超过 1024 token，注入时用父块摘要加上命中子块的全文。父块不被改成子块，也不写入向量库。超长父块的原文仍在对象存储。
- 嵌入模型是材料点名的 BGE-M3。加载失败就停在这一层，验收不能改成通过，也不换别的模型。
- 规范化全文用 SHA-256。哈希相同就不重新入库，也不重新嵌入。同一份正文从多个来源进来时只留一份，每个来源的标识都还在。
- 新版本按块比哈希。没变的块复用已有向量。变了的块重新嵌入。旧版里消失的块打上删除标记，不从库里物理抹掉。
- 旧版打上废止状态，并留下生效日期区间。默认读取滤掉废止和未生效。审计可以显式把废止版本一并带出。
- 新版本先把父块和子块写完，校验通过后才切换。切换完成前，查询仍读旧版。指针写失败时，查询被指回旧版。更新过程不先删后插，新旧两套子块在切换前同时还在。
- 变更事件走增量，只嵌入变了的块。另有定时对账：账上的哈希和正文重新算出来的哈希不一致时，仍走这条增量路径把漂移的块补上，不把整库先删掉再插入。

## 测试命令

```bash
python3 -m venv .venv
.venv/bin/pip install torch --index-url https://download.pytorch.org/whl/cpu
.venv/bin/pip install -e ".[dev]"
bash deploy/start-storage.sh
.venv/bin/pytest tests/index/live -q
```

第一次运行会下载 `BAAI/bge-m3`。权重缓存在仓库的 `.hf_cache/`，不进 git。

向量库、对象存储、元数据库都是存储层已经接通的服务。验收连的是 Milvus `127.0.0.1:19530`、MinIO `127.0.0.1:9000`、PostgreSQL `127.0.0.1:5432` 的库 `rag`。没有用内存字典充当这一层通过的依据。Elasticsearch 留给检索链路，这一层不写倒排。

存储层验收用的向量集合仍是 8 维的 `rag_child_vectors`。这一层另开 `rag_index_children`，维度是 BGE-M3 的 1024，避免把前面那一层的演示集合撑坏。两个集合都在同一个 Milvus 上，索引类型都是 HNSW。

## 最近一次结果：通过

`pytest tests/index/live -q`：23 passed in 45.74s。

BGE-M3 真的加载了。`BgeM3Embedder` 的模型编号是 `BAAI/bge-m3`，加载后的名字也是 `BAAI/bge-m3`，稠密向量维度是 1024。子块向量写入 Milvus 集合 `rag_index_children`，回读的索引类型是 HNSW，度量是 COSINE。用子块嵌入文本做近邻检索，能取回该子块，再按 `parent_id` 从对象存储读出父块原文。

同一命令之后又跑了 `pytest tests/storage/live tests/ingest -q`：36 passed。存储层 20 条、数据接入 16 条都还在。

## 自己选定的参数

材料写了区间、SHA-256、BGE-M3、废止和原子切换，没有写死下面这些实现细节。文档未写死。

- 用 sentence-transformers 在 CPU 上加载 `BAAI/bge-m3`。安装 PyTorch 时走 CPU 轮子，避免把带 CUDA 的大包拉下来。文档未写死。
- token 用 BGE-M3 自带分词器，不计特殊符号。父块、子块的区间都按这个计数。文档未写死。
- 短条款只在同一章内合并。跨章不并成一个父块。文档未写死。
- 标题路径用 ` / ` 拼成一行，放在子块正文前面。文档未写死。
- 子块内容哈希是「标题路径 + 子块正文」的 SHA-256。整篇去重哈希是规范化全文的 SHA-256，不把来源标识算进去。文档未写死。
- 父块摘要取条款编号加正文开头，最多 48 token。文档未写死。
- 表格行先写成「表头：字段名」再加「字段：单元格」。行太短就几行拼进一个子块，每一行仍带表头。能放进父块长度的表会附在父块原文后面；超长降级时表不留在父块正文里，只留带表头的行子块。文档未写死。
- 生效状态用 `pending`、`effective`、`obsolete`、`deleted` 四个词。旧版的结束日取新版生效日的前一天。消失块的删除标记在切换当时写上，切换前它们仍是生效，这样查询不会提前丢掉旧版。文档未写死。
- 索引账本放在元数据库的新表里：文档、来源、父块、子块、事件、查询指针。不改存储层原有的三张表。文档未写死。
- 向量集合名是 `rag_index_children`。文档未写死。
