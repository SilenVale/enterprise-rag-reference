## PDF 里要证明的规则

规则按架构里数据接入五格来写，用自己的话。哈希去重、嵌入、检索和生成不在这一层。

- 七个来源各自把文件交进来。形态覆盖转发、归档和附件。材料没有写出这七个系统的名字。
- 同一段规范化文本从多个来源进来时，每个来源的标识都留下。这一层不按内容并成一份，也不丢掉后来的来源。并成一份是索引层按哈希要做的事。
- 版面按栏内从上到下、栏与栏从左到右排阅读顺序。输入块的先后不算数。双栏夹具要能看出这个顺序。版面模型材料没有写死。
- 一页表尾没有结束边框，下一页第一张表又没有表头，就当成同一张表。合并之后表头还是前一页那一行，不重复贴一次。两条里缺一条，就仍然是两张表。
- 没有文本层，或者文本层占比过低的页，改走 OCR。盖章挡住的字要有一条夹具。OCR 产出走同一道质量闸门。引擎材料没有写死。
- 字符保有率是解析产出的字符数除以原文可提取字符数。低于阈值就失败。材料举的例子是 95%，这是示例，不是写死的线。双栏只剩半栏时，这一道必须失败。
- 表格闸门比对行列数，并抽查单元格。表头被多贴一行时，行列数对不上。
- 失败不静默丢掉。先换解析参数，或者改走另一条 OCR。多次仍然失败，写入元数据库里已经有的解析失败队列。队列里的文件不会出现在交给索引的结果里。队列写不进去就抛错，这份文件不能当成已经入库。

## 测试命令

```bash
python3 -m venv .venv
.venv/bin/pip install -e ".[dev]"
sudo pg_ctlcluster 16 main start
.venv/bin/pytest tests/ingest -q
```

库、角色和连接串沿用存储层：`postgresql://rag:rag-storage@127.0.0.1:5432/rag`。角色或库还不存在时，用 `deploy/start-storage.sh` 里建立 PostgreSQL 的那一段。那份脚本还会拉起另外三个存储，这一层的测试不连接它们。

人工队列的通过依据是 `tests/ingest/live`。它写入存储层元数据库的 `parse_failure_queue`，再按来源读回。写失败那一条用会抛错的替身，只证明抛错之后不会把文件当成已经入库，不能代替上面的读回。

## 自己选定的参数

材料写了七个来源、阅读顺序、跨页表、OCR 兜底和 95% 这个例子，没有写死下面这些名字和数。文档未写死。

- 七个适配器叫制度库、邮件、即时消息、公文、附件、扫描库、共享目录。前三个形态是归档、转发、转发，公文也是转发，附件是附件，扫描库和共享目录是归档。文档未写死。
- 版面不用某个点名的模型，按块的坐标分栏：相邻块的横向空隙不小于栏间距就换栏，栏内再按纵坐标从上到下。文档未写死。
- 默认栏间距 36，重试时收成 12。同一行的纵向容差是 4。空隙被默认间距并成一栏时，同一行只留最左边的一块，右栏因此在字符保有率上失败，再用更窄的间距重试。文档未写死。
- 文本层占比低于 0.5 就走 OCR。等于 0.5 仍走文本层。文档未写死。
- OCR 用两个可替换的区域读取器：`region-reader` 会丢掉盖章挡住的字，`region-reader-stamp` 把那段字补回。文档未写死。
- 字符保有率阈值取材料的示例 0.95。写进验收时注明这是示例。文档未写死。
- 来源取文件最多试 3 次。解析最多换 3 组参数：默认分栏、更窄栏间距、盖章感知识别。文档未写死。
- 没有文本层的页，原文可提取字符用夹具里的对照文本。材料没有写扫描件拿哪一份文本当除数。文档未写死。

空白不计入字符数。表头是否重复交给表格闸门，不靠字符数变长来拦截。
