# 合成制度

这里的制度是虚构的「砚台示范单位」。名字只用来把文件叫开。它不是任何一家机构的制度，也不代表真实客户。条文用来把后面的契约跑通：版面能读、来源能留、版本和权限能标、条款号和金额能在原文里对上。

这一目录只有夹具。不在这里做分块、嵌入、检索、生成或评测打分。`evaluations.json` 是待跑的条目，不是评测报告，里面没有指标。

页面的坐标、表格和印章，沿用数据接入已经在测的那些判定，好让同一套规则能落到这些文件上。块在文件里的先后不算阅读顺序。栏与栏隔得够开，按现在的默认栏间距就会先读完左栏再读右栏。上一页的表不封底、下一页第一张表又没有表头，才合成一张，表头只留前一页那一行。没有文本层的扫描页走识别；章盖住的那一段，普通识别会丢掉，盖章感知那一路才把字补回来。同一段文字从多个来源进来时，每一份都带着自己的来源标识。

金额和条款号都写在对应条文里。后面做出口校验时，答案里的数要能在被引用的那一版原文中找到同一个写法。

## 双栏

`documents/two-column.json`，文档 `syn-duty`《外出办事须知》。

四块字分居左右两栏，文件里的排列故意不是阅读顺序。读的时候应先从上到下读完左栏的第1.1条、第1.2条，再读右栏的第1.3条、第1.4条。左栏预支上限是 750元，右栏住宿上限是 420元/晚，伙食现行标准是 100元/日。

## 跨页表格

`documents/cross-page-table.json`，文档 `syn-rate-table`《费用标准表》。

首页表有表头，底边没有封口，行到住宿为止。次页开头那张表没有表头，只有伙食一行，底边是封上的。合并后仍是同一张表，表头不重复贴。市内交通 80元/日 只出现在合并后的表行里，条款号是第2.1条，正文段落里没有这个数。住宿 420元/晚 在第2.2条，伙食 100元/日 在第2.3条。第2.0条只说明夜间交通不再单列，不写旧金额。

## 扫描件，含盖章遮挡

`documents/scan-stamp.json`，文档 `syn-seal`《用印留存办法》，来源是扫描库里的归档。

这一页没有文本层。整页文字在图像层。印章压住第8.4条，里面的工本费是 36元。丢掉这一句之后，字符保有率过不了现有闸门；把这一句补回之后，规范化文本里才同时有第8.4条和 36元。

## 同一份文件多来源

`documents/multi-source.json`，文档 `syn-submit`《报销交单时限》。

同一段规范化文本交来三次：制度库、归档，文件号 `syn-submit`；邮件、转发，同一个文件号；附件、附件，还是同一个文件号。三份的正文都是第5.1条，时限是 15个工作日。三份都要留下，不能在这一层并成一条来源。

## 修订

`documents/revision-v1.json` 与 `documents/revision-v2.json`，同为文档 `syn-meal`《伙食补贴办法》。版本关系在 `versions.json`。

第3.1条两版文字相同，内容哈希一样，以后可以复用，不必重嵌。第3.2条从 100元/日 改成 120元/日。第3.9条只在旧版。第3.5条只在新版，金额是 40元。新版正文已经写全，状态仍是未生效，切换没有完成，查询应继续读旧版。所以「现行伙食补贴」在切换前对得上的数是旧版第3.2条的 100元/日，不是 120元/日。

## 废止

`documents/abolished.json`，文档 `syn-legacy`《旧夜间交通补贴口径》。

第9.1条写每次 60元，状态是废止，并带生效起止日期。默认检索不应把它当现行依据；审计可以显式调出来。60元 只出现在这一份里。现行说法在费用标准表的第2.0条：夜间交通不再单列，表内第2.1条才是现在的市内交通标准。答案如果写出 60元，要么对不上现行引用里的原文，要么引用了这份废止版本。

## 权限

`documents/restricted.json`，文档 `syn-comp`《内部津贴分档》。角色范围在 `permissions.json`。

这份的权限是 `internal-comp`，并写明对实习生隐藏。第6.2条的核心岗津贴是 1800元/月。实习生的允许范围只有 `staff`，提问时这份不应出现在候选里，对应的拒答是权限不足。正式员工的允许范围包含 `internal-comp`，可以引用第6.2条，金额仍要和原文一致。其余制度的权限是 `staff`，实习生可以看见。审计另外可以调出废止版本，但那不是默认检索。

## 条款编号

`documents/clause-number.json`，文档 `syn-clause`《设备租赁限额》。

第7.3条和第7.4条都以完整的条款号写在各自条文开头，方便以后按原始编号精确对上，而不是只靠拆开的数字。第7.3条的上限是 1350元。旁边第7.4条是另一个数，980元。问第7.3条时，不该把 980元 当成这一条的金额。

## 金额

`documents/amount.json`，文档 `syn-amount`《一次性补贴》。

第4.6条写明一次性安置补贴是 2400元。评测条目里留了一个条文中不存在的错数 2500元，给以后的数字校验当反例：这个数在整套语料里都找不到。

## 评测条目

`evaluations.json` 分三组：采样、边界构造、已修复 badcase。条数按这份语料能指到的问题来，不另造规模。

采样问的是住宿上限、交单时限、用印工本费、第7.3条的租赁上限，以及正式员工可见的核心岗津贴。

边界五条：切换前仍读旧版伙食补贴；废止的夜间补贴不能当现行依据；住宿上限要同时看第1.3条和第2.2条；实习生看不到内部津贴；市内交通 80元/日 只在跨页表里。

已修复的错例是把第4.6条说成 2500元。正确引用里的数是 2400元。
